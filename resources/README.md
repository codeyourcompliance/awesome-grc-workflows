# Resources

This directory curates external resources that help readers understand, inspect, implement, or practise bounded GRC workflows.

Resources may include:

- official regulatory or standards guidance;
- official product documentation;
- open-source tools and technical documentation;
- public implementation articles and cases;
- incident, audit, enforcement, and post-incident material;
- public courses, labs, datasets, and external challenges.

## Selection criteria

A resource should be included only when:

- it is publicly accessible and independently inspectable;
- its relevance to one or more bounded workflows can be explained;
- its source and publisher are identifiable;
- it adds practical or explanatory value beyond a promotional landing page;
- its limitations are stated where they matter;
- its inclusion does not imply endorsement of every claim, method, or product it contains.

Prefer primary and official sources where available. Open-source tools should link to the authoritative project repository or documentation.

## Resource roles

A resource may serve one or more roles:

- **contextual evidence** — supports terminology, constraints, failure modes, implementation analysis, or capability analysis;
- **learning resource** — helps readers understand the workflow or domain;
- **implementation resource** — provides a tool, method, or documented example;
- **practice resource** — provides a lab, dataset, course exercise, or external challenge.

State the role and relevance instead of listing a bare link.

## Boundaries

External resources do not replace employer evidence for workflow publication eligibility.

Do not:

- add weak links merely to meet a quota;
- treat product marketing as proof that an employer needs or intends to buy software;
- treat a course or challenge as evidence of recurring employer demand;
- copy substantial portions of third-party material;
- imply that inclusion establishes universal best practice;
- publish confidential, personal, production, or commercial information.

Maintainer-owned resources are optional. After removing all maintainer-owned links, the repository and each workflow page must still provide independent public value.

## Suggested entry format

```markdown
- [Resource title](public-url) — Publisher. Resource role and why it is relevant. Key limitation, if material. Last checked: YYYY-MM-DD.
```

Topic-specific resource guides should be created only when enough high-quality material exists to make the guide independently useful.
